# Диаграмма классов сервисов SmartWallet

## Общее описание

Диаграмма изображает архитектуру сервисного слоя приложения SmartWallet: два основных класса-сервиса (`TransactionEndpointService` и `TransactionService`), реализуемые ими интерфейсы, а также зависимости, внедряемые через конструктор (dependency injection). Диаграмма демонстрирует принцип инверсии зависимостей — сервисы зависят от абстракций (интерфейсов), а не от конкретных реализаций.

## Классы сервисов

### TransactionEndpointService

Сервис для управления конечными точками транзакций (transaction endpoints). Обеспечивает полный набор CRUD-операций для сущности «конечная точка транзакции».

**Ключевые методы:**
- `GetListByUserIdAsync` — получение списка конечных точек транзакций по идентификатору пользователя
- `CreateAsync` — создание новой конечной точки транзакции
- `UpdateAsync` — обновление существующей конечной точки транзакции
- `DeleteAsync` — удаление конечной точки транзакции

**Зависимости:** `IUnitOfWork`, `ISmartWalletValidateService`, `IMapper`

### TransactionService

Сервис для управления транзакциями. Реализует операции создания, удаления и получения списка транзакций пользователя.

**Ключевые методы:**
- `GetListByUserIdAsync` — получение списка транзакций по идентификатору пользователя
- `CreateAsync` — создание новой транзакции
- `DeleteAsync` — удаление транзакции

**Зависимости:** `IUnitOfWork`, `ISmartWalletValidateService`, `IMapper`

## Интерфейсы

### ITransactionEndpointService

Определяет контракт для работы с конечными точками транзакций. Включает полный набор CRUD-операций: `CreateAsync`, `DeleteAsync`, `GetListByUserIdAsync`, `UpdateAsync`.

### ITransactionService

Определяет контракт для работы с транзакциями. Включает операции: `CreateAsync`, `DeleteAsync`, `GetListByUserIdAsync`.

## Зависимости

### Общие зависимости (используются обоими сервисами)

| Зависимость               | Назначение                                                                           |
|---------------------------|--------------------------------------------------------------------------------------|
| `IUnitOfWork`             | Единица работы — координация доступа к данным и сохранение изменений                 |
| `ISmartWalletValidateService` | Валидация бизнес-правил и данных                                                |
| `IMapper`                 | Маппинг между сущностями домена и DTO                                                |

### ISmartWalletValidateService

Интерфейс сервиса валидации бизнес-правил и данных. Используется обоими сервисами для проверки корректности моделей перед выполнением операций.

**Методы:**
- `ValidateAsync<TModel>(model, token)` — асинхронная валидация модели данных. Обобщённый метод, принимающий модель любого ссылочного типа и токен отмены. Выбрасывает исключение при нарушении бизнес-правил.

### IMapper

Интерфейс маппинга объектов (AutoMapper). Используется для преобразования между сущностями домена и DTO.

**Методы:**
- `Map<TDestination>(source)` — маппинг исходного объекта в новый объект типа `TDestination`
- `Map(source, destination)` — маппинг значений из исходного объекта в существующий целевой объект

## Связи

### Связи реализации (implements)

Каждый класс-сервис реализует соответствующий интерфейс:

- `TransactionEndpointService` реализует `ITransactionEndpointService`
- `TransactionService` реализует `ITransactionService`

На диаграмме обозначаются пунктирной стрелкой с треугольником (`..|>`).

### Связи зависимостей (uses)

Оба сервиса получают зависимости через конструктор (constructor injection). На диаграмме обозначаются пунктирной стрелкой (`..>`) с подписью «uses»:

- `TransactionEndpointService` и `TransactionService` зависят от `IUnitOfWork`, `ISmartWalletValidateService`, `IMapper`
