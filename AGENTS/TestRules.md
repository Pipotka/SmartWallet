# Unit тесты
## Тесты для сервисов
### Используемые Nuget пакеты
Для написания unit тестов в этом проекте используются следующие Nuget пакеты:
- "Ahatornn.TestGenerator" Version="1.1.29";
- "FluentAssertions" Version="8.5.0";
- "Microsoft.EntityFrameworkCore.InMemory" Version="8.0.10";
- "Microsoft.NET.Test.Sdk" Version="17.14.1";
- "Microsoft.Testing.Platform" Version="1.8.1";
- "Moq" Version="4.20.72";
- "xunit" Version="2.9.3";
### Правила
- Тесты для сервисов располагаются в директории Service.Tests.
- Классы тестов именуются по шаблону "{НазваниеСервиса}Tests".
- Summary для тестов должно соответствовать следующему паттерну "Тесты на <see cref="ТестируемыйКласс"/>".
- Название теста должно соответствовать следующему паттерну `<Название тестируемого метода>Should<Ожидаемый результат>`;
- Если тестируемый метод являетя асинхронным и в его названии есть постфикс Async - не добавляй этот постфикс в название теста и в summary;
- Пиши summary к тестам. summary должно начинатся с названия тестируемого метода без постфикса Async. После названия метода нужно написать какой результат ожидам получить в этом тесте;
- Тест должен быть разделён на секции Arrange, Act и Assert используя комментарии, например: `// Arrange`. Между прямыми слешами и названием секции должен быть пробел;
- Для настройки моков используются методы-расширения для моков. Классы с этими методами расположены в директории "UnitTests.Services.Infrastructure\Mock\Extensions". Если для настройки мока не существует метода-расширения и предпологается, что настраивать мок подобным образом будем неоднократно - нужно создать новый метод для настройки мока. При создании нового метода используй в качестве референса уже существующие методы-расширения.
- При тестировании метода сервиса нужно писать отдельные тесты для проверки каждого выбрасываемого исключения.
